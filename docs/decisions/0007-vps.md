# ADR 0007 — Dedicated VPS, plan size and bootstrap path

Date: 2026-09-25 · Status: accepted

## Context
The briefing fixed a dedicated Hostinger KVM 2. While buying, the founder asked whether KVM 1 is
enough and whether the existing personal VPS (n8n in Docker) could be shared.

## Decision
- **Dedicated VPS, never shared with the founder's n8n machine.** The agent holds root on this
  machine; sharing would expose personal credentials and tie the company's rebuild/hardening cycle
  to personal workloads (CLAUDE.md rule 6). Cost of isolation: one KVM 1 (~R$30/month).
- **Start on KVM 1 (1 vCPU, 4 GB, 50 GB NVMe).** Workload is Node scripts, a webhook server, Caddy
  and Claude Code sessions; the model runs at Anthropic, the database at Supabase. Upgrade in place
  (KVM 2 → 4) when the weekly report shows sustained load > 1 or swap use. Only upgrades are
  possible, no downgrades.
- Add-ons: Monarx malware scanner (free) on; paid daily backups off (state lives in Supabase, the VPS
  is rebuildable from `infra/vps/setup.sh`); Docker manager off (systemd, no containers).
- Created 2026-09-25, Ubuntu 24.04, public IP **2.25.249.69**, SSH keys `founder-notebook` and
  `patentsonar-agent` registered in Hostinger.

## Bootstrap path
The Claude Code cloud container cannot open TCP/22 (egress is HTTPS through a policy proxy), so the
first bootstrap is run by the founder from their machine over SSH; the repository is public, so the
VPS pulls the script from GitHub directly:

```bat
ssh -i %USERPROFILE%\.ssh\patentsonar_founder root@2.25.249.69 "curl -fsSL https://raw.githubusercontent.com/ratbragaia/patentesimas/main/infra/vps/setup.sh | REPO_URL=https://github.com/ratbragaia/patentesimas.git BRANCH=main bash"
```

After bootstrap, `harden.sh` disables password login; key login is proven to work by the command
itself. Take a Hostinger snapshot right after. Ongoing operation happens on the VPS itself
(Claude Code installed by the script) and via systemd timers; the cloud session keeps the
repository and documentation.
